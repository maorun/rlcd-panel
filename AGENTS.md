# AGENTS.md

## Project Overview

`rlcd-panel` contains the standalone `Arduino CLI` (`esp32:esp32@3.3.12`) firmware for the **Waveshare ESP32-S3-RLCD-4.2** (`B0GF23YC3Y`) reflective LCD panel. The device scans BLE advertisements from up to five **SwitchBot IP65 Indoor/Outdoor Thermo-Hygrometers** (`WoIOSensor`, `B0DXPHZMMP`), reads the onboard `SHTC3` sensor over I²C, and renders a 4-tile climate dashboard onto the 400×300 `ST7305` RLCD screen.

## Repository Structure

- `rlcd_panel/sketch.yaml`: Pinned `arduino-cli` build profile `rlcd_panel_s3` (`esp32:esp32:esp32s3:CDCOnBoot=cdc,FlashSize=16M,PSRAM=opi,PartitionScheme=app3M_fat9M_16MB` on `esp32:esp32@3.3.12`).
- `rlcd_panel/board_pins.h`: Hardware GPIO constants and I²C addresses for `ESP32-S3-RLCD-4.2`.
- `rlcd_panel/battery_monitor.h`: 18650 Li-ion battery voltage and percentage decoder (`GPIO4` ADC1_CH3 with 3.0× divider).
- `rlcd_panel/battery_monitor.h` also holds `CycleTracker` (charge cycle counter: 100 points of discharge are one cycle; NVS key `cycle_count`, one write per charge event or whole cycle) and `CycleStore`.
- `rlcd_panel/switchbot_ble.h`: Header-only BLE parser (`Company ID 0x0969` Manufacturer Data + `UUID 0xFD3D` Service Data) and 5-slot sensor registry (`MAX_SWITCHBOT_SENSORS`). `SwitchBotRegistry::upsert(reading, BleFormat)` counts each rejected packet in `BleRejectStats` (`WOIO`, `METER`, `BTHOME`, `ATC`, `THERMOPRO`; each counter saturates at 65535; the MAC of the last reject; `resetRejects()` runs at the start of `scanOnce()`; no `PersistentState` field; the console command `STATUS` shows `BLE rejected=<N> last=<MAC|--> woio=<N> meter=<N> bthome=<N> atc=<N> thermopro=<N>` before `POWER`). `JumpGuard` holds a packet that differs by more than 8.0 C or 25 %RH from a stored reading younger than 10 minutes as pending (no RTC state): a second packet of the MAC within 1.0 C and 5 %RH takes the slot, a packet near the stored value or `SwitchBotRegistry::endScan()` (after each scan in `scanOnce()`) drops it and counts it in `BleRejectStats::jumps` (saturates at 65535; `STATUS` appends ` jumps=<N>` to the `BLE` line; `BleRejectMetrics.jumps` parses it); a held packet keeps `updated_ms`, so a wake interval above 600 s turns the guard off; a held packet makes `upsert` return false and does not reach `ScanCompletion`. `SwitchBotRegistry::anyStale` feeds `ALERT_SENSOR_LOST` (one 440 Hz note when a valid slot is stale for 30 min).
- `rlcd_panel/switchbot_ble.h` also holds `ReceptionHistory` (BLE reception rate of each registry slot: one 24-bit mask and one scan count (saturates at 24) for each of the 5 slots; `recordScan` runs after each BLE scan in `setup()` and shifts the mask of each occupied slot, bit 0 is set when the `packet_count` of the slot grew; an empty slot keeps mask 0 and count 0; `PersistentState::resetSlot` clears it; 16 bytes in `PersistentState::reception` just before the checksum (mask as 3 bytes little-endian plus count for each slot); a count above 24, a mask bit beyond the counted scans or an entry of an empty slot is rejected; a power-on sets it to 0). The console command `STATUS` shows `RECEPTION s1=<N>/<M> ... s5=<N>/<M>` (`--` for an empty slot) after `BLE`. `ReceptionMetrics` in `Diagnostics.swift` parses it (`--` gives `nil`, `s1=x/24` throws `ParseError.badLine`); `DiagnosticsView` shows the rate and a warning symbol below 50 %. `STATE_VERSION` is 58. The stats view shows the rate as `RX <N>%` on the RSSI line (`DashboardView::formatReception`, scale 1, right-aligned to x = 392, `y + 11`; `RX --` for fewer than 6 counted scans and an empty history; inverted below 50 %; not drawn when the gap to the RSSI line is below `RX_GAP_PX` 4; `SystemInfo::reception`, calculated on each render, no RTC state).
- `rlcd_panel/switchbot_ble.h` also holds `RejectLog` (the rejected packets of the last BLE scan: 8 entries with MAC, `BleFormat`, `RejectReason` (`FULL`, `UNASSIGNED`, `SLOT_OFF` (text `DISABLED`), `JUMP`, `WEAK`) and a count that saturates at 255; one entry for each MAC, a later packet of the MAC raises the count and keeps the first reason; each further MAC raises `dropped`, which saturates at 255; `SwitchBotRegistry::resetRejects()` clears it at the start of `scanOnce()`; a JumpGuard drop in `endScan()` or by a near packet records `JUMP`; `scanOnce()` copies it to `PersistentState::reject_log`, 73 bytes just before the checksum (9 bytes for each entry plus `dropped`); a reason above `WEAK`, a used entry with count 0, an unknown format, a repeated MAC, a used entry after an unused one, a stray byte in an unused entry and `dropped` with a free entry are rejected; a failed scan start clears the copy). The console command `REJECTS` (`SerialConsoleRunner::showRejects`) replies `BEGIN REJECTS`, the header `mac,format,reason,count`, one row for each entry, `DROPPED,<N>` when MACs were lost and the `CRC32` line; `ERR BAD_ARG` for extra text; RTC copy only, no card access; runs on USB and on BLE at each `ble_console` level. `tests/fixtures/rejects_reply_sample.txt` holds a sample. `STATE_VERSION` is 68.
- `rlcd_panel/window_latch.h`: Header-only `WindowLatch` (open window badge, key `window_drop_c`: 0 is off, else 1.0 to 5.0 C in 0.1 C steps, default 0; one bit for each tile in `PersistentState::window_tiles`, bit 0 onboard, bits 1 to 10 slots, only tiles in `climate_alert_tiles`; `WindowLatch::Anchors` in `PersistentState::window_anchors` keeps for each tile the peak of the current half window (`ref`), the peak of the half window before (`prev`) and a stamp; the bit sets when the reading is at least the limit below the larger peak, the window is 15 minutes (the peak can reach back up to 1.5 windows with a reading interval above a minute) or `DeviceConfig::windowDropMs()` (the longest wake interval plus the scan time) when that is longer; an open tile keeps its lowest reading in `ref` and releases when the reading is half the limit above it or 2 hours after the set; a stale slot, an empty slot, an invalid reading, a tile outside the mask and limit 0 clear bit and anchor; `PersistentState::restartWindowOnPowerChange` clears the anchor of a closed onboard tile when the power source changes, because `usb_temp_offset_c` steps the reading). `DashboardView` draws the inverted `W` badge beside `V` and `D`. `PersistentState::recordWindowChanges(previous, current, now)` records `EventCode::WINDOW_OPEN` 22 (detail low byte tile 0 to 10, high byte 1 open, 0 closed; `EventRing::MAX_CODE` is 23). `PowerManager::WINDOW_SIZE` (the limit in tenths, the bits, 11 anchors of 8 bytes) sits just before the checksum; a bit above bit 10, a limit outside the range, a peak beyond 120 C, a previous peak on an open tile and an open tile without a reference are rejected; `resetSlot` clears and `swapSlotsByUser` swaps the bit and the anchor of a slot. No chime, no telemetry flag, no `STATUS` field. `STATE_VERSION` is 71, `KEY_COUNT` is 96. `docs/display_preview_window.png` shows the badge.
- `rlcd_panel/wall_latch.h`: Header-only `WallLatch` (wall humidity badge: one bit for each tile in `PersistentState::wall_tiles`, bit 0 onboard, bits 1 to 10 slots; the bit sets when `ClimateMath::wallSurfaceRh` of the tile with `wall_frsi_pct` and the `outdoor_slot` reading is at or above `mold_alert_limit_rh` and releases more than 3 %RH below it; an empty or stale tile, the outdoor tile, a stale or empty outdoor slot, an invalid result and `wall_frsi_pct` 0 clear the bit; `DashboardView` draws the inverted `C` badge beside `V`, `D` and `W`; no chime, no telemetry flag; the `STATUS` line `LATCH` ends with ` wall=<3 hex digits>`; `PowerManager::WALL_SIZE` 2 bytes just before the checksum, a bit above bit 10 is rejected, `resetSlot` clears and `swapSlotsByUser` swaps the bit; `STATE_VERSION` is 72; `docs/display_preview_wall.png` shows the badge).
- `rlcd_panel/atc_ble.h`: Header-only parser `AtcBleParser` for Xiaomi thermometers with custom firmware (`UUID 0x181A` Service Data). The length selects the format: 13 bytes ATC (MAC, temperature and battery mV big-endian), 15 bytes pvvx (little-endian). Other lengths, a temperature outside -50 to 100 °C, a humidity above 100 %RH and a battery above 100 % are rejected. The readings use the `SwitchBotRegistry` slots.
- `rlcd_panel/thermopro_ble.h`: Header-only parser `ThermoProBleParser` for ThermoPro BLE thermometers (TP357, TP357S, TP358, TP359, TP393) broadcasting Manufacturer Specific Data with header `0xC2`. Decodes temperature (16-bit signed little-endian in 0.1 °C), humidity (uint8 %RH) and battery (bars or percentage). The readings use the `SwitchBotRegistry` slots (`BleFormat::THERMOPRO`).
- `rlcd_panel/climate_math.h` also holds `ClimateMath::heatIndexC(temp_c, rh_pct)` (NOAA Rothfusz regression and its two corrections, below 26.7 C or below 40 %RH it returns the air temperature, NaN for NaN, infinite or out-of-range input). The stats view shows it as `FEELS <T>C` (`DashboardView::formatFeels`, scale 1, right-aligned to x = 392, `y + 3`, unit from `temp_unit`, `FEELS --` for an empty or stale slot or an invalid result), calculated on each render. The `COMFORT --` label of an empty slot moved to `y + 11` (`COMFORT_EMPTY_Y_OFFSET`). `DashboardView::formatAbsHumidity` shows `AH <N.N>G` (`ClimateMath::absoluteHumidityGm3`, g/m3) at scale 1, right-aligned to x = 392, at `y + 54` on the record line; `AH --` for an empty or stale slot or an invalid result; it is not drawn when the gap to the record text is below 4 px (`AH_GAP_PX`); calculated on each render, no RTC state.
- `rlcd_panel/ble_telemetry.h`: Header-only `BleTelemetryCodec`: one Manufacturer Data frame (company ID `0xFFFF` plus an 18-byte payload = 20 bytes; with the 3-byte flags field and the 2-byte AD header 25 of 31 bytes): version 1, sequence (`boot_count` low byte), cell percentage (255 unknown), alert mask, valid tile mask, four tiles of `int16` 0.01 C little-endian and `uint8` 0.5 %RH, CRC-8 `0x31` (`Shtc3Codec::computeCrc8`). An empty or stale tile has its mask bit cleared and zero bytes; the temperature stays in Celsius. `shouldBroadcast` is false for `ble_broadcast_enabled=0`, a low battery alert and the empty battery protection. `broadcastTelemetry()` in `rlcd_panel.ino` advertises it non-connectable for `BleTelemetryCodec::advertiseMs` (1500 ms on battery power, 750 ms for each of the 2 pages; 2000 ms on USB power; interval 20 ms) after `refreshSensors()` and stops before the deep sleep. `tests/fixtures/ble_telemetry_vectors.txt` holds the shared hex vectors.
- `rlcd_panel/sparkline.h` also holds `ClimateHistory::usb_mask` (24 bits, bit 0 is the newest onboard sample; `record` shifts it on each onboard push and sets bit 0 on USB power; 3 bytes little-endian in `PersistentState` just before the checksum; a bit beyond the onboard sample count is rejected; a power-on sets it to 0). `CALIB N` uses the battery hours only for the onboard `temp_offset_c` proposal when 3 or more exist, and adds the line `USB hours=<n> bat_hours=<n> usb_temp_offset=<x> usb_temp_diff=<x|-->` after the onboard `SENSOR` line plus the proposal `usb_temp_offset_c=<x>` (the active value minus `usb_temp_diff`, clamped to -5.0 to 0.0 C) with 3 or more USB and 3 or more battery hours; `CalibrationReply.UsbSplit` parses it. `STATE_VERSION` is 58.
- `rlcd_panel/sparkline.h` also holds `ClimateHistory::restore` (refills the 24-hour histories after a power-on from `SdLogCodec::parseClimateRow` rows of `climate_v6_YYYYMM.csv`: the newest run of at most 24 rows, not older than 24 hours, no step above 90 minutes; onboard and slots with a fixed MAC only; `usb_mask` from the `usb` column; `last_sample_ms` follows the newest row; no change for an invalid RTC time or non-empty histories). `SdLogger::restoreHistories` reads the last 8192 bytes of the current and, with fewer than 24 rows, of the previous month file; `restoreHistoriesFromCard` in `rlcd_panel.ino` runs it for a power-on only.
- `rlcd_panel/sparkline.h` also holds `WeekHistory::restore(rows, count, now)` (refills the seven days after a power-on from `SdLogCodec::parseDailyRow` rows of `daily_v5_YYYY.csv`: `WeekHistory::RestoreRow`, 83 columns `SdLogCodec::DAILY_COLUMNS`; a sensor needs both values of a pair, an empty pair is a gap, a half pair rejects the row; only the 7 days before the RTC date count, a later row of a day wins, a day without any pair is no data; the RTC date becomes the stamp; no change for an invalid, stopped or untrusted RTC time, a week with a stamp or a value, and rows without a day in range). `SdLogger::restoreWeek` reads the last `DAILY_TAIL_BYTES` (4096) of the file of the current year and, from 1 to 7 January, of the previous year (`DailyRowBuffer`, 14 rows); `restoreHistoriesFromCard` in `rlcd_panel.ino` runs it for a power-on only. The RTC layout and `STATE_VERSION` do not change.
- `rlcd_panel/sparkline.h`: Header-only 24-hour relative humidity trend: `HumidityHistory` (24 hourly samples, 0.1 %RH steps, 0 to 100 %RH), `ClimateHistory` (onboard + 5 SwitchBot slots = 6 histories, hourly gate) and the `Sparkline` scaler and renderer (`MIN_SPAN` 5.0 %RH). `HumidityHistory::countAbove(limit_tenths)` counts the samples strictly above the limit; the stats view shows it as `MOLD <N>H` (`DashboardView::formatMold`, scale 1, right-aligned to x = 392, `y + 21`) with the limit `mold_alert_limit_rh`, calculated on each render.
- `rlcd_panel/st7305_framebuffer.h`: Header-only 400×300 1-bpp framebuffer (`15,000` bytes) with `ST7305` 2×4 block pixel packing and 5×7 text primitives. `crc32()` gives the CRC-32 (IEEE, same value as `SerialCrc32`) of the 15,000 bytes; call it after `invert()`.
- `rlcd_panel/frame_refresh.h`: Header-only `FrameRefresh` (CRC-32 of the last flushed frame plus the skip counter, 5 bytes in `PersistentState::frame` just before the checksum; a counter above 60 or skips without a CRC are rejected; a power-on sets both to 0). `flushFramebuffer()` in `rlcd_panel.ino` skips the panel start and the flush when `shouldSkip` is true: timer wakeup, no view change (mode or chart sensor against the RTC copy), known and equal CRC-32, fewer than 60 skips in a row. The 61st cycle flushes. A power-on, a `KEY` wakeup, a view change and the empty battery screen always flush. `g_panel.begin()` runs in `ensurePanelStarted()` at the first flush. The console command `PATTERN` starts the panel itself and calls `FrameRefresh::invalidate()`, so the next wake cycle flushes the normal view. `STATE_VERSION` is 58.
- `rlcd_panel/st7305_panel.h`: ESP32-S3 hardware SPI driver for the `ST7305` RLCD controller.
- `rlcd_panel/shtc3_sensor.h`: Sensirion `SHTC3` CRC-8 (`0x31`) and raw frame decoder. `Shtc3Codec::classify` gives the `Shtc3Result` of one read (`OK`, `NACK`, `SHORT`, `CRC`; `readOnboardShtc3` returns it). `Shtc3Codec::shouldRetry(result, attempt)` is true only for a failed attempt 0; `readShtc3WithRetry` runs the read, then on a failure the soft reset `0x805D` with a 1 ms wait (`readOnboardShtc3` in `rlcd_panel.ino`) and one more read (at most 17 ms of awake time); `Shtc3Health::record` counts only the final result, and `retried` (`uint16_t`, saturates at 65535) counts each retry, also one that succeeds. `Shtc3Health` counts the failed reads by cause (each counter saturates at 65535) and the failures in a row (`run`, saturates at 255; a good read sets it to 0). `PersistentState::shtc3` stores 9 bytes (three `uint16_t` counters, one `uint8_t` run, one `uint16_t` `retried`) just before the checksum; a power-on sets them to 0 and a run above the sum of the counters is rejected. The console command `STATUS` shows `SHTC3 nack=<N> short=<N> crc=<N> run=<N> retried=<N>` before `POWER`. The diagnostics view shows `SHTC3 ERR: <N>` (sum of the counters) at x = 190, y = 44, inverted while `run` is 3 or more.
- `rlcd_panel/battery_monitor.h` also holds `AwakeTimeStats` (measured awake time: `millis()` just before the deep sleep; only a timer wakeup on battery power adds a sample, `AwakeTimeStats::wanted`; last value, maximum and a running mean over 24 samples, each value saturates at 65535 ms; 6 bytes in `PersistentState::awake` just before the checksum: last, maximum, and one `uint16_t` with the mean in 32 ms steps (high 11 bits) and the count (low 5 bits); a count above 24, a last value above the maximum or values without a sample are rejected; a power-on sets them to 0). `BatteryHistory::estimate(reading, scan_saved_ms, awake)` uses the measured mean instead of `AWAKE_MS` from 8 samples. `STATE_VERSION` is 58.
- `rlcd_panel/power_manager.h`: Header-only deep sleep manager: wakeup timer maths, wakeup cause decoding, wake cycle state machine, and checksummed RTC-memory state (registry, battery, view mode).
- `rlcd_panel/power_manager.h` also holds `ResetReasonCodec` (`esp_reset_reason()` to text; `PANIC`, `INT_WDT`, `TASK_WDT`, `WDT` and `BROWNOUT` are abnormal) and `AbnormalResetCounter` (NVS namespace `rlcd`, key `abn_resets`, `uint16_t`, saturates at 65535; `setup()` writes only after an abnormal reset, `ResetCountStore` on the board).

## Hardware & Firmware Invariants

1. **Pre-Flash Backup:** Run `./scripts/backup-firmware.sh` to dump NVS and the full 16 MB flash before the first flash upload.
2. **Pre-Flash Preview Mandatory:** Always generate and inspect `docs/display_preview.png` via `./scripts/generate-display-preview.sh` before flashing firmware to the board.
3. **GPIO Output Ordering on ESP32 Core 3.3.12:** Always call `pinMode(pin, OUTPUT)` before `digitalWrite(pin, level)`.
4. **ST7305 Framebuffer Packing:** The 400×300 display uses `15,000` bytes with column-major block packing and inverted Y (`byte_index = (x / 2) * 75 + ((299 - y) / 4)`, `bit = 7 - (((299 - y) % 4) * 2 + (x % 2))`).
5. **MicroSD Card (`SD_MMC`):** Always call `SD_MMC.setPins(38, 21, 39)` before `SD_MMC.begin("/sdcard", true)`.
6. **Build Cleanliness:** Do not commit `build/`, `rlcd_panel/build/`, `firmware_backups/`, or `test_runner` binaries.
7. **Deep Sleep Cycle:** `setup()` runs one wake cycle (restore, scan, render, save, `esp_deep_sleep_start()`); `loop()` never runs. Use the RTC-backed `nowMs()` for timestamps, not `millis()`, which restarts after sleep. Call `PowerPlatform::releasePinsAfterSleep()` first in `setup()`: it frees the KEY pin and the held display pins (`CS`, `DC`, `RST`) after they were driven high.
8. **SHTC3 Calibration Offset:** The onboard SHTC3 temperature sensor is subject to PCB self-heating and applies a default calibration offset of `-1.9 °C` (`Shtc3Codec::DEFAULT_TEMP_OFFSET_C`).
