# AGENTS.md

## Project Overview

`rlcd-panel` contains the standalone `Arduino CLI` (`esp32:esp32@3.3.12`) firmware for the **Waveshare ESP32-S3-RLCD-4.2** (`B0GF23YC3Y`) reflective LCD panel. The device scans BLE advertisements from up to three **SwitchBot IP65 Indoor/Outdoor Thermo-Hygrometers** (`WoIOSensor`, `B0DXPHZMMP`), reads the onboard `SHTC3` sensor over I²C, and renders a 4-tile climate dashboard onto the 400×300 `ST7305` RLCD screen.

## Repository Structure

- `rlcd_panel/sketch.yaml`: Pinned `arduino-cli` build profile `rlcd_panel_s3` (`esp32:esp32:esp32s3:CDCOnBoot=cdc,FlashSize=16M,PSRAM=opi,PartitionScheme=app3M_fat9M_16MB` on `esp32:esp32@3.3.12`).
- `rlcd_panel/board_pins.h`: Hardware GPIO constants and I²C addresses for `ESP32-S3-RLCD-4.2`.
- `rlcd_panel/battery_monitor.h`: 18650 Li-ion battery voltage and percentage decoder (`GPIO4` ADC1_CH3 with 3.0× divider).
- `rlcd_panel/battery_monitor.h` also holds `CycleTracker` (charge cycle counter: 100 points of discharge are one cycle; NVS key `cycle_count`, one write per charge event or whole cycle) and `CycleStore`.
- `rlcd_panel/switchbot_ble.h`: Header-only BLE parser (`Company ID 0x0969` Manufacturer Data + `UUID 0xFD3D` Service Data) and 3-slot sensor registry. `SwitchBotRegistry::upsert(reading, BleFormat)` counts each rejected packet in `BleRejectStats` (`WOIO`, `METER`, `BTHOME`, `ATC`; each counter saturates at 65535; the MAC of the last reject; `resetRejects()` runs at the start of `scanOnce()`; no `PersistentState` field; the console command `STATUS` shows `BLE rejected=<N> last=<MAC|--> woio=<N> meter=<N> bthome=<N> atc=<N>` before `POWER`). `SwitchBotRegistry::anyStale` feeds `ALERT_SENSOR_LOST` (one 440 Hz note when a valid slot is stale for 30 min).
- `rlcd_panel/atc_ble.h`: Header-only parser `AtcBleParser` for Xiaomi thermometers with custom firmware (`UUID 0x181A` Service Data). The length selects the format: 13 bytes ATC (MAC, temperature and battery mV big-endian), 15 bytes pvvx (little-endian). Other lengths, a temperature outside -50 to 100 °C, a humidity above 100 %RH and a battery above 100 % are rejected. The readings use the `SwitchBotRegistry` slots.
- `rlcd_panel/climate_math.h` also holds `ClimateMath::heatIndexC(temp_c, rh_pct)` (NOAA Rothfusz regression and its two corrections, below 26.7 C or below 40 %RH it returns the air temperature, NaN for NaN, infinite or out-of-range input). The stats view shows it as `FEELS <T>C` (`DashboardView::formatFeels`, scale 1, right-aligned to x = 392, `y + 3`, unit from `temp_unit`, `FEELS --` for an empty or stale slot or an invalid result), calculated on each render. The `COMFORT --` label of an empty slot moved to `y + 11` (`COMFORT_EMPTY_Y_OFFSET`). `DashboardView::formatAbsHumidity` shows `AH <N.N>G` (`ClimateMath::absoluteHumidityGm3`, g/m3) at scale 1, right-aligned to x = 392, at `y + 54` on the record line; `AH --` for an empty or stale slot or an invalid result; it is not drawn when the gap to the record text is below 4 px (`AH_GAP_PX`); calculated on each render, no RTC state.
- `rlcd_panel/ble_telemetry.h`: Header-only `BleTelemetryCodec`: one Manufacturer Data frame (company ID `0xFFFF` plus an 18-byte payload = 20 bytes; with the 3-byte flags field and the 2-byte AD header 25 of 31 bytes): version 1, sequence (`boot_count` low byte), cell percentage (255 unknown), alert mask, valid tile mask, four tiles of `int16` 0.01 C little-endian and `uint8` 0.5 %RH, CRC-8 `0x31` (`Shtc3Codec::computeCrc8`). An empty or stale tile has its mask bit cleared and zero bytes; the temperature stays in Celsius. `shouldBroadcast` is false for `ble_broadcast_enabled=0`, a low battery alert and the empty battery protection. `broadcastTelemetry()` in `rlcd_panel.ino` advertises it non-connectable for 100 ms (interval 20 ms) after `refreshSensors()` and stops before the deep sleep. `tests/fixtures/ble_telemetry_vectors.txt` holds the shared hex vectors.
- `rlcd_panel/sparkline.h`: Header-only 24-hour relative humidity trend: `HumidityHistory` (24 hourly samples, 0.1 %RH steps, 0 to 100 %RH), `ClimateHistory` (onboard + 3 SwitchBot slots, hourly gate) and the `Sparkline` scaler and renderer (`MIN_SPAN` 5.0 %RH). `HumidityHistory::countAbove(limit_tenths)` counts the samples strictly above the limit; the stats view shows it as `MOLD <N>H` (`DashboardView::formatMold`, scale 1, right-aligned to x = 392, `y + 21`) with the limit `mold_alert_limit_rh`, calculated on each render.
- `rlcd_panel/st7305_framebuffer.h`: Header-only 400×300 1-bpp framebuffer (`15,000` bytes) with `ST7305` 2×4 block pixel packing and 5×7 text primitives.
- `rlcd_panel/st7305_panel.h`: ESP32-S3 hardware SPI driver for the `ST7305` RLCD controller.
- `rlcd_panel/shtc3_sensor.h`: Sensirion `SHTC3` CRC-8 (`0x31`) and raw frame decoder. `Shtc3Codec::classify` gives the `Shtc3Result` of one read (`OK`, `NACK`, `SHORT`, `CRC`; `readOnboardShtc3` returns it). `Shtc3Health` counts the failed reads by cause (each counter saturates at 65535) and the failures in a row (`run`, saturates at 255; a good read sets it to 0). `PersistentState::shtc3` stores 7 bytes (three `uint16_t` counters, one `uint8_t` run) just before the checksum; a power-on sets them to 0 and a run above the sum of the counters is rejected. The console command `STATUS` shows `SHTC3 nack=<N> short=<N> crc=<N> run=<N>` before `POWER`. The diagnostics view shows `SHTC3 ERR: <N>` (sum of the counters) at x = 190, y = 44, inverted while `run` is 3 or more.
- `rlcd_panel/power_manager.h`: Header-only deep sleep manager: wakeup timer maths, wakeup cause decoding, wake cycle state machine, and checksummed RTC-memory state (registry, battery, view mode).
- `rlcd_panel/power_manager.h` also holds `ResetReasonCodec` (`esp_reset_reason()` to text; `PANIC`, `INT_WDT`, `TASK_WDT`, `WDT` and `BROWNOUT` are abnormal) and `AbnormalResetCounter` (NVS namespace `rlcd`, key `abn_resets`, `uint16_t`, saturates at 65535; `setup()` writes only after an abnormal reset, `ResetCountStore` on the board).
- `rlcd_panel/device_config.h`: Header-only `config.ini` parser (`DeviceConfigParser`, `DeviceConfig`) for the settings from the MicroSD card: ranges, defaults, 4096-byte limit, including the sensor names `onboard_name` and `slot1_name` to `slot3_name`, `log_retention_months`, `noise_alert_limit_db`, `chime_alert_mask` (0 to 255, default 255; bit 5 is `ALERT_VENTILATE`, bit 6 is `ALERT_SENSOR_BATTERY`, bit 7 is `ALERT_HEAT`) and `ble_broadcast_enabled` (0 or 1, default 0; 1 byte after `heat_alert_limit_c` in the config trailer; see `ble_telemetry.h`) and `heat_alert_limit_c` (0 is off, else 27 to 45 C; `AlertEvaluator` sets `ALERT_HEAT` when `ClimateMath::heatIndexC` of a tile in `climate_alert_tiles` is at or above the limit and releases it 2 C below or without a usable reading; 1 byte after `chime_repeat_h` in the config trailer; chime of two short high notes; `BEEP 7`), `sensor_battery_limit_pct` (0 to 50, default 10, 0 is off; `SensorBatteryLatch` in `switchbot_ble.h` sets a per-slot latch at or below the limit, releases at limit + 5 %, and drives the inverted `BAT LOW` text in the tile), `outdoor_slot` (0 is off, 1 to 3 selects the outdoor registry slot of the ventilation advice), `ventilate_limit_rh` (50 to 80 %RH, default 60; `VentilateLatch` in `ventilate_latch.h` drives the `V` badge on a tile) `climate_alert_tiles` (0 to 15, default 15; bit 0 is the onboard sensor, bits 1 to 3 are the registry slots; `AlertEvaluator` reads only these tiles for `ALERT_FREEZER` and `ALERT_HUMIDITY`, a tile outside the mask counts as a tile without a usable reading, mask 0 clears both bits; the other alerts ignore it) `battery_offset_mv` (-300 to 300 mV, default 0; `BatteryMonitor::decodeMillivolts` adds it to the cell voltage before each limit; the first check after a power-on uses the RTC copy) `slot_release_h` (0 to 168 h, default 0 is off; `PersistentState::releaseDeadSlots` runs once per wake cycle before the BLE scan and clears a slot without a fixed MAC and without a packet for this time: reading, 24-hour histories, ventilation and battery latch via `resetSlot`; a fixed MAC slot never releases) `display_invert` (0 or 1; `St7305Framebuffer::invert()` flips each byte after the render and before the flush) and `sensor_stale_min` (5 to 240 min, default 30; `DeviceConfig::staleTimeoutMs()` raises it to `wake_interval_s` + 4 s and feeds each `isStale` call) and `wake_interval_s` (30 to 900 s; `PowerManager::powerConfig` passes it to `PowerConfig::sleep_interval_s` on battery power, USB power keeps 60 s) and `temp_unit` (`C` or `F`, default `C`; `ClimateMath::toDisplay(temp_c, unit)` converts only the text of the tiles, the dew point line, the record line and the console command `STATUS`; the card files, limits, offsets and alerts stay in Celsius; any other value is rejected; 1 byte after `night_wake_interval_s` in the config trailer) and `night_wake_interval_s` (0 is off, else 60 to 1800 s; on battery power while `QuietHoursWindow::isActive()` is true `PowerManager::powerConfig` uses it as `sleep_interval_s`; an invalid RTC time uses `wake_interval_s`; `staleTimeoutMs()` uses the larger of the two intervals) and `chime_repeat_h` (0 is off, 0 to 24 h; 1 byte after `temp_unit` in the config trailer; `AlertEvaluator::repeat` sounds the lowest active bit again after this time since `PersistentState::last_chime_ms` (4 bytes, before the audio flags byte; set by the last chime or by a rising edge); `ALERT_CHARGE_FULL` never repeats; mute, quiet hours and a cleared `chime_alert_mask` bit skip the reminder and advance the stamp, so no chime plays when the quiet hours end). `ConfigRejects` holds the count of rejected lines (saturates at 255) and the line numbers of the first four; unknown keys are no errors. The values and the rejects live in `PersistentState` (RTC memory); only a power-on, a `KEY` wakeup and the console command `SET` (USB power) mount the card. Never read Wi-Fi credentials from the card.
- `rlcd_panel/device_config.h` also holds `DeviceConfigCheck` (host check of a `config.ini` text: values, `REJECTED line=<N>`, `REJECTED count=<N>`; exit codes 0, 1, 2).
- `rlcd_panel/sd_logger.h`: Header-only CSV logger (`SdLogCodec`, `SdLogger`). Format version 4: 21 columns (climate plus `noise_rms`, `noise_db`, `noise_band`, `noise_events`, `noise_l10`, `noise_l90`), file `/sdcard/climate_v4_YYYYMM.csv`; the old `climate_v3_YYYYMM.csv` and `climate_v2_YYYYMM.csv` files stay unchanged, and the console and the retention still handle them. `DailyPlanner` and `SdLogger::appendDaily` write one summary row per day (30 columns: min/max/mean of the 24-hour histories, `noise_min_db`, `noise_max_db`, `noise_peak_db`, `noise_peak_hour`, `noise_events_sum`) to `/sdcard/daily_v2_YYYY.csv`; the old `daily_v1_YYYY.csv` files (27 columns) stay unchanged, and the console and the retention handle both. `DailyNoiseStats` in `PersistentState::daily` collects the peak (the first hour wins on a tie), its local hour and the event sum (saturates at 65535) at each hourly write; no valid reading gives empty fields at the first hourly write after local midnight; the stamp lives in `PersistentState::daily`. After each hourly write the logger deletes only matching files older than `log_retention_months` (never the current month; a daily file counts as December of its year) and reads the free space for the diagnostics view. The wake cycle that writes the hourly record runs one 5 s `NoiseSampler` window (50 blocks of 100 ms give `noise_l10` and `noise_l90`), also after a timer wakeup; a low battery alert skips it. Other timer wakeups keep the microphones off, except on USB power, where the clap listener runs.
- `rlcd_panel/sd_logger.h` also holds `EventRing` (16 events in `PersistentState`: local RTC time, `EventCode`, 16-bit detail; a full ring drops the oldest event and counts it) and `SdLogger::appendEvents`. The hourly write appends the events to `/sdcard/events_v1_YYYY.csv` (columns `time,event,detail`, first row `EVENTS_DROPPED` after a loss) and clears the ring only after a successful write. `LIST`, `DUMP` and `scripts/dump-logs.sh` accept `events_v1_YYYY.csv`; the retention counts it as December of its year. `EventCode` values 8 to 10 (`RESET` with the `ResetReason`, `SLOT_ASSIGN` with slot in the high byte and `BleFormat` in the low byte, `SLOT_RELEASE` with the slot number; slots count from 1; `ResetReasonCodec::recordsEvent`, `SwitchBotRegistry::takeAssigned`, `PersistentState::recordSlotEvents`) are valid in the RTC ring check (`EventRing::MAX_CODE` is 10). `STATE_VERSION` is 45.
- `rlcd_panel/serial_console.h` also holds `BleChunkSink` (output sink of the BLE console: notifications of `max(1, mtu - 3)` bytes, same bytes as on USB serial, `flush()` sends the last chunk, a failed notification ends the reply) and `BleConsoleBridge` (RX bytes through `SerialLineAssembler` and `SerialConsole::parse`; `ble_console` 1 gives `ERR READ_ONLY` for `SET` and `TIME SET`, each level gives `ERR NOT_OVER_BLE` for `DUMP` and `SCAN`; one central, `onDisconnect` clears the partial line). `BleConsoleUuids` in `ble_telemetry.h` holds the Nordic UART UUIDs. `PowerManager::bleConsoleAllowed` (USB power and `ble_console` not 0) gates the `BleConsoleService` of `rlcd_panel.ino`, which runs commands in the loop task through the same dispatch as USB serial. `ble_console` (0 to 2, default 0; 1 byte after `ble_broadcast_enabled` in the config trailer) is a `config.ini` key. `STATE_VERSION` is 45.
- `rlcd_panel/audio_loopback.h`: Header-only speaker to microphone loopback test: `GoertzelFilter`, `LoopbackDetector` (1 kHz, pass at -60 dBFS and 50 % tone share), `AudioLoopback::run` (skips while muted, in quiet hours and with volume 0; powers down in the order amplifier, `ES8311`, `ES7210`, bus on every path) and the ESP32 `LoopbackHal`. A `BOOT` long press in the diagnostics view starts it (`BootButtonController`).
- `rlcd_panel/clap_detector.h`: Header-only double-clap detection: `TransientCounter` (counts the transients of the 5 s `NoiseSampler` window with the same detector front end, so `NoiseReading::events` needs no longer microphone time), `ClapDetector` (transient rise 20 dB in under 5 ms, decay under 100 ms, 150 ms to 600 ms between two claps, third clap ignored) and `ClapListener` (20 ms audio frames over the `ES7210` HAL). Only an awake board listens: continuously on USB power, in the 3 s `KEY` grace window on battery. `PowerManager::clapListenMode` sets the gate.
- `rlcd_panel/serial_console.h`: Header-only USB serial console: `SerialConsole` parser (`LIST`, `INFO`, `STATUS` (live sensor snapshot from `g_state`, `SerialStatusSnapshot`, with the line `RESET reason=<TEXT> abnormal=<N|-->` before `POWER`, and the line `RUNTIME h=<N|--> samples=<N> cycles=<N.N|--> scan_saved_ms=<N>` after `POWER`: `BatteryHistory::estimate`, `CycleTracker::cycleTenths` and `g_scan_saved_ms`, RTC copy and NVS only, no state change), `CONFIG` with `REJECTED line=N` lines, `VERSION` (build identity: `VERSION fw=… git=… core=… state=… built=…` and a `CRC32` line from constants, no card access), `EVENTS` (event ring from the RTC copy: `BEGIN EVENTS`, header `time,event,detail`, rows from `SdLogCodec::formatEventRow` oldest first, a ring with lost events starts with the `formatEventsDroppedRow` row of the current RTC time, `CRC32` line; `EVENTS` with text gives `ERR BAD_ARG`; no card access, the ring stays; `SerialConsoleRunner::showEvents`; `scripts/dump-logs.sh --events`), `SCAN` (one 4 s BLE scan: `SerialConsoleRunner::scan` runs `consoleScanOnce` of the sketch, which fills a `ScanCollector` (`switchbot_ble.h`, 16 MACs, the strongest RSSI wins, `DROPPED,<N>` row for further MACs) while the BLE callback leaves the registry alone; reply `BEGIN SCAN`, header `mac,format,rssi,slot,temp_c,rh_pct,battery_pct`, one row for each MAC, `CRC32` line; `ERR BAD_ARG` for extra text, `ERR SCAN_FAILED`; no card access; the command blocks the console loop and the clap listener for about 4 s and starts and stops BLE itself, which only hardware proves), `PATTERN <0|1|2>` (test pattern: `St7305Framebuffer::fillPattern`, 0 black, 1 checkerboard, 2 border with cross; `SerialConsoleRunner::showPattern` flushes with `g_panel.flush` without `display_invert`, replies `OK PATTERN <N>`, another value `ERR BAD_ARG`; no card access; the next wake cycle renders the normal view), `HISTORY` (24-hour histories as CSV from the RTC copy: `BEGIN HISTORY`, header `sensor,age_h,temp_c,rh_pct,noise_db`, one row per stored hour of sensor 0 to 3, `CRC32` line; - `rlcd_panel/firmware_version.h`: Header-only build identity: `FIRMWARE_VERSION` (`1.0.0`), `ARDUINO_CORE_VERSION` (`3.3.12`) and the macro `RLCD_GIT_HASH` (default `unknown`). `scripts/flash-firmware.sh` sets the hash with `--build-property 'compiler.cpp.extra_flags=-DRLCD_GIT_HASH="<hash>"'` (`-dirty` for a changed tree). - `rlcd_panel/dashboard_view.h`: Decoupled 4-tile climate dashboard renderer shared between firmware and preview generator.
- `rlcd_panel/rlcd_panel.ino`: Main firmware entry point (`setup()` / `loop()`).
- `scripts/backup-firmware.sh`: Backs up NVS (`0x9000`, `20 KB`) and full flash (`0x0`, `16 MB`) via `esptool` into `firmware_backups/` (mode `0700`).
- `scripts/generate-display-preview.sh`: Compiles and executes the bit-exact framebuffer renderer, generating `docs/display_preview.png` (dashboard), `display_preview_dashboard.png`, `display_preview_stats.png`, `display_preview_diagnostics.png`, `display_preview_spectrum.png`, `display_preview_chart.png`, `display_preview_low_battery.png`, `display_preview_quiet_hours.png`, `display_preview_ventilate.png` and `display_preview_inverted.png`.
- `scripts/dump-logs.sh`: Copies the monthly CSV logs over USB serial into the ignored directory `sd_logs/` and checks the CRC-32.
- `scripts/flash-firmware.sh`: Mandatory flash script that generates the display preview image first, compiles, and uploads to the board.
- `tools/check_config.cpp`: Host tool that runs the firmware `DeviceConfigParser` on one `config.ini` file (exit 0 ok, 1 rejected lines, 2 missing or oversized file). `scripts/check-config.sh <file>` builds and runs it (exit 3 for a build failure). Sample file: `tools/sample_config.ini`.

- `tests/test_firmware_logic.cpp`: Host C++17 unit test suite covering BLE packet parsing, registry management, framebuffer bit mapping, `SHTC3` CRC-8 decoding, and dashboard rendering.

## Hardware & Firmware Invariants

1. **Pre-Flash Backup:** Run `./scripts/backup-firmware.sh` to dump NVS and the full 16 MB flash before the first flash upload.
2. **Pre-Flash Preview Mandatory:** Always generate and inspect `docs/display_preview.png` via `./scripts/generate-display-preview.sh` before flashing firmware to the board.
3. **GPIO Output Ordering on ESP32 Core 3.3.12:** Always call `pinMode(pin, OUTPUT)` before `digitalWrite(pin, level)`.
4. **ST7305 Framebuffer Packing:** The 400×300 display uses `15,000` bytes with column-major block packing and inverted Y (`byte_index = (x / 2) * 75 + ((299 - y) / 4)`, `bit = 7 - (((299 - y) % 4) * 2 + (x % 2))`).
5. **MicroSD Card (`SD_MMC`):** Always call `SD_MMC.setPins(38, 21, 39)` before `SD_MMC.begin("/sdcard", true)`.
6. **Build Cleanliness:** Do not commit `build/`, `rlcd_panel/build/`, `firmware_backups/`, or `test_runner` binaries.
7. **Deep Sleep Cycle:** `setup()` runs one wake cycle (restore, scan, render, save, `esp_deep_sleep_start()`); `loop()` never runs. Use the RTC-backed `nowMs()` for timestamps, not `millis()`, which restarts after sleep. Call `PowerPlatform::releasePinsAfterSleep()` first in `setup()`: it frees the KEY pin and the held display pins (`CS`, `DC`, `RST`) after they were driven high.
8. **SHTC3 Calibration Offset:** The onboard SHTC3 temperature sensor is subject to PCB self-heating and applies a default calibration offset of `-1.9 °C` (`Shtc3Codec::DEFAULT_TEMP_OFFSET_C`).
